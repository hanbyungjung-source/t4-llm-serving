# Kaggle T4×2 LLM 자가호스팅 서빙·추론 최적화

무료 Kaggle 노트북의 **Tesla T4 두 장**(각 15GB, 전력 한도 70W, vCPU 4, RAM 30GiB)으로 **Qwen3.8 27B 멀티모달 모델(UD-Q4_K_XL, 약 17.6GB)** 을 **192K 문맥**으로 띄우고, **OpenAI 호환 API**로 외부 앱에 제공하는 개인 연구입니다(2026.09).

- 기반: [llama.cpp](https://github.com/ggml-org/llama.cpp) v0.5.0 (MIT License), 비교 엔진: [ExLlamaV3](https://github.com/turboderp-org/exllamav3)
- 클라이언트: 직접 만든 Windows 데스크톱 에이전트 [Local Desk](https://github.com/hanbyungjung-source/local-desk-agent)
- 진행 방식: GitHub Copilot 에이전트로 코드 작성과 실험 실행을 자동화했습니다. 목표와 고정 조건(품질 불변, 192K, 엄격 JSON 도구 호출), 판정 기준 승인, 운영 반영은 본인이 결정했고, 세부 후보 선택은 에이전트에 위임했습니다.

## 구성

```text
PC (Local Desk) ──HTTPS + API 키──▶ ngrok 고정 도메인 ──▶ Kaggle 노트북
                                                         └─ llama-server (127.0.0.1:8080)
                                                              T4 #0 ⇄ T4 #1  텐서 분할
                                                              본체 MTP 초안 3토큰 · Q8 KV · 192K
```

## 주요 결과

같은 세션·같은 입력(temp 0, seed 42)에서 운영판(b11000, 층 분할 + 별도 MTP 파일)과 채택 구성을 비교했습니다. 후보당 1회 실행입니다.

| 지표 | 기존 운영판 | 채택 구성 | 변화 |
|---|---:|---:|---:|
| 고정 4사례 생성 속도 | 23.46 t/s | 37.18 t/s | **+58%** |
| 정답 확정 20문항 생성 속도 (정답 수) | 18.77 t/s (20/20) | 34.11 t/s (20/20) | **+82%** |
| 33.6K 토큰 입력 처리 | 271 t/s | 337 t/s | +24% |
| 33.6K 문맥에서 생성 | 14.2 t/s | 27.5 t/s | +93% |
| 세션 시작 다운로드 | 3개 파일 약 19.9GB | 2개 파일 약 18.5GB | 초안 파일 1.37GB 제거 |
| 세션 시작 빌드 | 매번 약 25분 | 캐시 키·SHA 일치 시 생략 | 빌드 캐시 |

운영 반영 후 ngrok 경유 실측: 고정 4사례 **34.12 t/s**, 답변 바이트가 연구 드라이런과 4건 모두 동일했습니다. 키 없는 요청은 **401**로 거부됩니다.

### 이득의 원천

| 변경 | 효과 | 근거 |
|---|---|---|
| 층 분할 → **텐서 분할** (`--split-mode tensor`) | +23% | 층 분할은 두 GPU가 순차로 일함(nsys: 동시 실행 2ms, GPU별 바쁨 39%/53%) |
| 별도 초안 파일 → **본체 MTP 층을 초안으로** | +3%, GPU1 약 1.1GB 절약 | 본체가 검증하므로 출력 분포 불변 |
| 2~4토큰 검증 행렬곱 **MMVQ → MMQ** (`GGML_CUDA_MMVQ_MAX_BATCH=1`) | +28% | llama.cpp 전환표에 Turing 조정이 없음을 발견. 4열에서 MMQ가 모든 형식에서 1.04~1.52배 빠름. 1토큰 초안은 MMVQ 유지 |

llama.cpp 판 교체(b11000 → v0.5.0) 자체는 같은 토큰·같은 속도라 이득이 없었습니다.

## 병목 분석

nsys 추적과 연산 단위 측정으로 투기적 디코딩 한 라운드를 분해한 뒤 우선순위를 정했습니다.

- 라운드 153ms = 초안 약 25ms + 검증 약 116ms + CPU 약 14ms. 초안 시간의 대부분(21.7ms)은 **MTP 초안 출력 헤드(Q3_K, 248320×5120)** 이며 유효 대역폭 75GB/s에 그침
- 커널 시간의 81%가 양자화 행렬-벡터 곱(mmvq). 형식별 유효 대역폭: Q3_K 92 · Q4_K 145 · IQ4_XS 146~156 · Q5_K 181~265 · Q6_K 166~306 GB/s
- GPU 간 전송: P2P 9.9GB/s, 호스트 경유 6.3GB/s, 작은 메시지 왕복 약 18µs (PHB 연결이지만 P2P 가능)
- 두 GPU 모두 70W 전력 한도 근처에서 클럭이 내려가고, 연속 실행일수록 느려짐 → 후보 비교는 온도 회복 후 인접 실행끼리

## 품질 검증

속도를 위해 수치 경로를 바꾸는 후보는 기능 시험만으로 판단하지 않고, 로짓 단위로 비교했습니다.

| 검사 | 방법 | 기준 |
|---|---|---|
| 로짓 | wikitext-2 teacher-forcing(ctx 512, 2048토큰)으로 평균 KLD·top-1 일치·PPL 비 | 배치 크기만 바꾼 기준 자신의 차이(잡음 바닥) 이하, PPL 비 1±0.5% |
| 기능 | 고정 4사례 + 정답 확정 20문항(한국어 포함, 엄격 JSON 도구 호출) | 전부 정답, JSON 유효 |
| 긴 문맥 | 4,000줄 목록에서 바늘 찾기(33,651 입력 토큰, 192K 서버) | 정답 |
| 자원 | GPU 여유 128MiB 이상, 가용 RAM 4GiB 이상 | 192K에서 GPU 최소 여유 981/2173MiB |

| 구성 | 평균 KLD | top-1 일치 | PPL 비 |
|---|---:|---:|---:|
| 잡음 바닥 (기준 빌드, 배치 512·ub128) | 0.00193 | 97.89% | 0.9982 |
| 텐서 분할 + MMQ (채택) | 0.00173 | 97.94% | 1.0011 |

처음에 동결한 절대 기준(평균 KLD ≤ 5e-4, top-1 ≥ 99.5%)은 배치 크기만 바꾼 기준 빌드 자신도 통과하지 못해 측정 불가능한 기준으로 판단했고, 위의 잡음 바닥 기준으로 바꿨습니다. 변경 경위는 [연구 기록](docs/ENGINE-STUDY.md)에 남겼습니다.

### 기각·보류

- **층 분할 + MMQ** (24.54 t/s): temp 0 예열 사례에서 결정적으로 오답 → 기각
- **ExLlamaV3 텐서 병렬(NCCL)** (34.16 t/s): 엄격 JSON 문법·비전·192K Q8 KV·서버 API가 없어 기각. 네이티브 TP 백엔드는 동기화 시간 초과
- **MTP 초안 헤드 Q4_0 재양자화** (b11000에서 +4.3%): 모델 파일을 바꾸는 방식이고 열 제한과 겹쳐 판정 보류

## 서빙 운영 모듈

[server/kaggle_server.py](server/kaggle_server.py)는 표준 라이브러리만 사용하는 노트북용 운영 모듈입니다.

| 단계 | 동작 |
|---|---|
| 사전 점검 | T4 두 장·GPU 여유 메모리·디스크 확인, 아니면 시작 거부 |
| 모델 | 고정 리비전에서 다운로드, 파일별 크기·SHA-256 검증 |
| 런타임 | llama.cpp 태그·커밋 확인 후 MMVQ 임계 패치. 멱등이며, 위치를 못 찾거나 다른 판 패치가 있으면 거부 |
| 빌드 캐시 | 태그·커밋·패치 문자열·cmake 플래그·`nvcc` 버전으로 키를 만들고, 키와 SHA가 모두 맞을 때만 재사용 |
| 서버 | `127.0.0.1` 바인딩, API 키는 명령줄이 아닌 자식 프로세스 환경변수로만 전달 |
| 터널 | ngrok 고정 도메인. 키 없는 요청 401·정상 키·모델 ID를 확인한 뒤에만 공개. 인증 토큰은 파일·명령줄·출력에 남기지 않고, 모델 키와 Kaggle 환경변수는 터널 프로세스에서 제외 |
| 배포 | [server/make_notebook_cell.py](server/make_notebook_cell.py)가 모듈을 SHA-256 무결성 검사와 함께 노트북 셀에 내장 |

이 저장소의 생성기로 다시 만든 셀의 SHA-256(`63750444…`)은 실제 운영 노트북 셀의 기록값과 같습니다.

```python
# Kaggle 노트북: GPU T4 x2, Internet ON
# Secrets: LOCAL_DESK_API_KEY, NGROK_AUTHTOKEN, NGROK_DOMAIN
import kaggle_server as ks

server, tunnel, api_url = ks.launch_service()
```

## 한계

- 후보당 1회 실행이며 열·시간 변동이 ±5% 이상입니다(같은 판 21.19~23.46 t/s).
- **단일 사용자(동시 슬롯 1)** 기준입니다. 연속 배칭·다중 사용자 처리량은 측정하지 않았습니다.
- 33.6K 입력은 첫 토큰까지 약 100초가 걸립니다.
- temp 1 샘플링의 분포 동등성은 별도로 시험하지 않고 KLD로 대신했습니다.
- Kaggle 약관의 개인·비상업적 사용 범위에서 운영하며, 상시 호스팅 서비스가 아닙니다.
